# Scorecard

Status: draft by a worker, 2026-11-18; goals and targets are the owner's to set.

This is how well vbm-json is doing against the goals this repository states for itself. Every command is run from the repository root, with the pinned Lean on `PATH` (the repository says `mise exec -- ...`; in the drafting jail `mise` could not install offline, so the same Lean 4.35.0 was used from `~/.local/share/mise/installs`, which is what `mise exec` would run). Units: counts are counts, shares are hundredths of a percent, durations are seconds, sizes are bytes or lines. "Floor" starts equal to "now" and may only move toward better.

## Goals as the repository states them

1. **Verified by construction is priority 1; efficiency is priority 2.** `AGENTS.md:4-5`; the measure is the specified share of the executed mass of the exports and the size of the trust ledger, `docs/decisions/0001-vbm-json.md:29-30`.
2. **Correctness is a theorem, not a test: a proved reference parser, and the parser the exports run provably equals it.** `README.md:24`; `AGENTS.md:28` (only a `proved` claim in the obligation ledger may be called verified); `CONTRIBUTING.md:28` (the proved count and the specified share only go up).
3. **The specified share only rises and the unverified set only shrinks; nothing from `Std`, `Lean` or `LeanJsonProofs` is reachable from an export.** `AGENTS.md:29`; the floor `specified_share = 100` is in `scorecard.toml:191`.
4. **No `sorry`, `admit`, `axiom`, `unsafe`, `implemented_by`, `csimp`; a zero-warning build; only the standard axioms.** `AGENTS.md:26`, `AGENTS.md:45`, `README.md:27`.
5. **Bare metal: the verified core imports only `Init`, compiles to freestanding C and to a WebAssembly module with no imports; no libc.** `README.md:25`; `AGENTS.md:39`.
6. **The boundary never decides: C, loaders and bindings only move bytes; the hand-written code around the core is small and listed line by line.** `AGENTS.md:30`; `README.md:3`; bindings are generated plus at most 100 hand-written lines each, `AGENTS.md:40`.
7. **A trust ledger lists everything outside our control; a new boundary with no entry fails the gate.** `AGENTS.md:42`; `docs/trust-ledger.md:5` (the size of the unverified base is the most critical measure); `README.md:117`.
8. **Shared vectors, generated by the Lean reference and never by the fast code, run in every binding; JSONTestSuite is vendored.** `AGENTS.md:41`; `README.md:26`; `vectors/README:1-6`.
9. **Efficiency (priority 2): within 2x of the best scalar comparator (python json, serde_json) on the primary corpus.** `scorecard.toml:71` (the floor of the scorecard adapter); measured in `docs/perf/results.md`.
10. **Evidence that the checks can fail: the shim's mutants are killed, the proofs catch seeded changes of the fast parser.** `docs/mutants.md:3`; `README.md:113`; `scorecard.toml:52-66` (mutation), `scorecard.toml:120-130` (non-vacuity).
11. **Tier 1 is the only gate and stays fast: about 20 s for a one-module change, about 11 minutes cold.** `AGENTS.md:45`; `docs/decisions/0004-tier1-speed.md:54`.
12. **Pre-release now; packages named, nothing published.** `README.md:5`; `AGENTS.md:5`.

## Health today

- **Nothing regressed against what the repository itself gates on**: the specified share is 10000 (100.00%), unverified definitions 0, axiom offenders 0, forbidden constructs 0, warnings 0, ABI mismatches 0, pins intact, the vector check passes on 43708 rows.
- **Far from where the goals point: the proofs about what the exports run.** The goal is "correctness is a theorem" (goal 2) but only 6 of 22 claims are `proved`, 12 are partial or open, and 21 of 68 cited theorems are about functions the exports never reach. 82 of 297 reachable spec definitions are mentioned by no theorem, so the 100.00% specified share says where code lives, not that it is constrained. The printer, the tape, and every policy claim except the parser's are partial.
- **The trusted base is not yet fully written down**: 9 of 35 required items have no contract or no test (goal 7). The trusted C is 527 lines, against about 450 stated in `README.md:113`.
- **Unmeasured here**: mutation score, non-vacuity, throughput against the scalar comparators (priority 2), and the Tier 1 times. All need a build host or the scorecard runner. The efficiency goal therefore has no number today.
- **Environment**: the Rust binding test cannot run here (no default `cargo` toolchain); it is a skip-in-spirit that fails, and the Python, wasm and native tests pass.
- **No target is set for any metric**, so no metric can be called far from target; the owner sets them.
- **Release**: nothing is published and there is no tag; consistent with "pre-release", but the repository states no release goal.

## What a steward would do first

1. Raise `proved-claims` and lower `proof-ledger-gaps` by closing the partial claims that the exports' own code reaches: first the printer claims (`print-parse-round-trip`, `print-output-is-accepted`, `print-tape-prints-the-value`), which also lowers `ledger-theorems-unreached`.
2. Lower `spec-definitions-unconstrained` (82) with theorems about the reachable definitions no statement mentions, so that the 10000 `specified-share-hundredths-percent` means "constrained", and lower `trust-ledger-gaps` (9) by writing the missing contracts and tests.
3. Measure the unmeasured on a build host (`mutation-score-hundredths-percent`, `nonvacuity-score-hundredths-percent`, `throughput-vs-best-scalar-permille`, `tier1-seconds-warm`, `tier1-seconds-cold`) and set their floors, then bring `test-scripts-failing` to 0 by giving the Rust test a toolchain.
